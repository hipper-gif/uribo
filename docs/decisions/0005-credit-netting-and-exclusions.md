## Context（背景・なぜ決める必要があるか）

仕訳帳(6).csv（2026年度4〜7月）の全科目突合（2026-08-26）で、TKCの部門損益とうりぼーの差のうち「仕様上の差」を除いた**真の差**は、全部 `aggregateBeauty` が**費用科目の貸方を無視**していることに帰着した:

| 科目 | 何が貸方に来るか | 影響 |
|---|---|---|
| 6312 法定福利費 | 従業員負担の**雇用保険**が月末給与仕訳で `CR 6312/雇用保険料`（預り金ではない） | うりぼー `legal_welfare` が毎月 +2.7〜5.2k/店 過大（総支給に含まれる従業員負担分の二重費用化。4ヶ月で 32,877円） |
| 5211 材料仕入 | 返品返金（2026/06 守口 SHEIN 8,257 `DR 1113 / CR 5211 012`） | cogs 84,109 → 正は 75,852 |
| 6225 備品消耗品 | 立替金への振替（2026/07 寝屋川 森下・個人負担分 500 `DR 1155 / CR 6225 011`） | supplies 32,463 → 正は 31,963 |

一方で、貸方を素直に足し引きすると壊れるケースも2つあった:

1. **期中修正（部門間の振替）**: 税理士が5月の家賃部門逆転を 2026/07/01 に `DR 6215 011 121,000 / CR 6215 012 124,000 ＋ DR 6219 011 3,000` で直した。7月の集計に入れると寝屋川 rent が 242,000・守口 200,000 に化ける。修正対象の5月はうりぼー側が `--skip 6215,6219` で正しい値を保持済みなので、振替伝票は無視するのが正しい。
2. **引当計上（非現金）**: 6213 従業員賞与 12,500/店/月 は `CR 2126 賞与引当金`「賞与引当金計上」。年間見込の月割りで現金は動かず、実支給時は2126の取崩で損益に出ない。うりぼー（キャッシュ視点）では費用にしない。

さらに「期中修正」を**摘要だけ**で判定すると、2026/05/01 の PayPay手数料（`DR 6227 6,526×2 / CR 1122 売掛金`・摘要「期中修正」）のような**本物の費用**まで落とした（dry-runで発覚）。

## Decision（確定した主要決定＝1決定1行）

| # | 決定 | 理由（1行） |
|---|------|------|
| D29 | **美容部門の費用科目（5xxx/6xxx）の貸方は、同じ科目の借方から差し引いてネットにする**（明細には負の額で残す） | TKCの残高推移表・部門損益はネット値。ネットにして初めて突合が合い、従業員負担雇用保険・返金・立替の過大計上が消える |
| D30 | **部門振替（期中修正）は伝票単位で除外する**: 伝票内に「摘要 期中修正/部門修正/部門振替」or「同一損益科目の両建て（部門違い）」があり、かつ**伝票内の科目が全部 損益科目(4/5/6xxx)** のもの（`correctionVoucherKeys`）。相手科目にBS科目（売掛金・現金等）があれば本物の費用として残す | 摘要だけだと PayPay手数料のような本物の費用を落とす。片側だけの行（`DR 6219 011 3,000`）を拾うには伝票番号が要るので `ParsedJournalRow.voucher` を追加 |
| D31 | **引当計上（`CR 2126` or 摘要「引当金計上」）は集計しない**。6213 は `bonus` にマッピングするが、引当以外（実支給を直接6213に載せた場合）でしか来ない | 非現金。実支給の賞与はTKC経由で入らないため `bonus` は給与明細から手入力（facts F17） |
| D32 | **監査 J5 で「除外した伝票」を一覧表示**（部門振替＝警告・修正対象月のうりぼー値を確認せよ／引当＝情報）、**J6 でネット後に負になった科目**を警告 | 「TKCにある数字がうりぼーに来ない」理由を見える化する。黙って落とすと次に見る人が二重計上を疑う |
| D33 | **6226 福利厚生費の `uribo_codes` に `welfare` を入れ、`welfare` を is_active=1 に戻す**。2026/04 両店に残っていた `welfare` 3,300（5/23 の追加→非アクティブ化の残骸・`water_supply` と二重）は削除 | `uribo_codes` に無い細目は0初期化の対象外＝旧値が消えない。CLAUDE.md の予約条件（water_supply 以外の福利厚生費が発生したら再有効化）が 2026/05 守口 スターバックス 4,030 で成立 |
| D34 | **TkcCompare の 6219/6226 マッピングを tkcImport・RECON_RULES と揃える**（`water_supply` は 6226 側） | 比較ページで「水道光熱費 +3,300／福利厚生費 うりぼー0」に見えていた（二重に見える正体） |

## Consequences（結果・トレードオフ）

- 2026年度4〜7月を再取込して反映済（5月は `--skip 6215,6219`）。変わった値: `legal_welfare` 全月両店（−2,670〜−5,247）、6月守口 `cogs` −8,257、7月寝屋川 `supplies` −500、預かり税の再計算。これで科目別の残差は全て「仕様上の差」だけになった。
- 返金だけが翌月にずれた場合、その月の科目がネットで負になり得る → J6 が警告し、取込値は負のまま（前月と合わせて見る）。
- 期中修正の伝票を落とすので、**修正対象の月のうりぼー値が本当に正しいか**は人が確認する（J5 の警告文）。修正対象月を再取込するときは `--skip` が要る（5月は F13）。
- 貸方ネットは美容部門コードが付いた貸方だけ。部門コード無しの貸方（全社一括の戻し）は拾えない。

## 未決・保留

- 5月寝屋川 HPB 132,000（F14・発生ベースで残す決定）は7月までのCSVでも対応する支払いが現れていない。累計で +132,000 の差として残る。HPBの請求書で5月分の有無を確認する。
