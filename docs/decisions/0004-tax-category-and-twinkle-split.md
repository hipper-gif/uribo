## Context（背景・なぜ決める必要があるか）

仕訳帳(6).csv（2026年度4〜7月）でTKCとうりぼーを全科目突合した結果（2026-08-26）:

1. **「法定費用」区分の達成率が意味を失っていた。** 区分には `legal_welfare`（法定福利費）と `withholding_tax`（預かり税＝実質の納付消費税）が同居していたが、目標側は TargetSetting の一括算出が `legal_welfare = 給与×14.5%` しか埋めず、`withholding_tax` の目標は空だった。実績には両方乗るため、寝屋川4月で 目標125,000 / 実績213,469（171%）のように見え、杉原氏から「目標との%が変わりすぎる」「消費税が法定福利の枠にあるのはおかしい」と指摘された。
2. **Twinkle代の店別計上に取込が耐えられない。** TKCの部門損益は 6117 を寝屋川(011)に美容全額（例170,000）で一本計上しており、店別で見ると寝屋川が約95k悪く・守口が約59k良く出る。杉原氏の判断は「うりぼーの折半（65,000/65,000・介護40,000）が正」で、税理士/ちょぼまる（Clio）側の仕訳入力を店別計上へ寄せる方向。ところが `classifyOutsourcing` は「金額が65,000なら和田委託」を Twinkle名義判定より**先**に評価するため、店別計上した瞬間に Twinkle代65,000を和田委託と誤判定して守口の給与へ足してしまう。

## Decision（確定した主要決定＝1決定1行）

| # | 決定 | 理由（1行） |
|---|------|------|
| D24 | **区分「税金」を新設し、`withholding_tax` / `vat_purchase` / `net_payable_tax` を「法定費用」から移す**（`EXPENSE_CATEGORIES` は 法定費用 の直後） | 消費税は売上連動で、法定福利費（人員計画依存・削減不可）とは性質も予測ロジックも違う。同じ枠だと「法定福利費が2倍」に誤読される |
| D25 | **TargetSetting の保存時に派生項目（預かり税・仕入消費税）の目標を自動算出して書く**（DataEntry の実績保存と同じ `calcDerivedAmount`） | 目標側にも消費税を乗せないと「税金」区分の達成率が成立しない。人手で目標消費税を入れる運用は続かない |
| D26 | **CLI `--recalc-only` に `--data-type 目標` を追加**し、保存を経ていない年度の目標側の預かり税を穴埋めできるようにする | D25 は保存を通った目標にしか効かない。2026年度の既存目標は CLI で12ヶ月分を書き込んだ（2026-08-26） |
| D27 | **`classifyOutsourcing` の優先順位を「①和田 ②今道 ③Twinkle代タグ/本人名 ④金額65,000 ⑤Twinkle名義(守口→委託/寝屋川→Twinkle)」に変更**。摘要規約＝「Twinkle代 寝屋川」「Twinkle代 守口」「Twinkle代 介護」／「和田 委託販売手数料」／「今道 …」 | 仕訳入力を Clio/ちょぼまる に寄せる前提なら、金額より**タグ**を一次の判定材料にできる。金額判定はタグも本人名も無い行の最後の砦に格下げ |
| D28 | **Twinkle代の按分は計上パターンで切り替える**: 両店にTwinkle代が立っていれば店別の額をそのまま（介護分は美容部門外）、片店に一本なら従来どおり `(合計 − TWINKLE_KAIGO_DEDUCT 40,000) ÷ 2` | 移行前後の月が混在しても再取込で壊れない。判定は `twinkleByStore.size >= 2` |

## Consequences（結果・トレードオフ）

- 「税金」区分は DataEntry / MonthlyReport / TkcImport監査R7 に自動で出る（`EXPENSE_CATEGORIES` を回しているため）。R7 の許容乖離は 30%（売上連動）。
- 目標側の消費税は目標売上・目標経費から機械的に決まる。**目標を編集して保存すれば追従する**（保存を経ない直接SQL編集は追従しない→ CLI `--data-type 目標` で穴埋め）。
- 店別計上へ移行する際の**前提**: 守口の Twinkle代65,000 には必ず「Twinkle代 守口」のタグ（または本人名）を付ける。付いていないと金額判定で和田委託へ倒れる（取込プレビューのプルダウンで手直しは可能）。
- RECON_RULES 'labor' の `offsetIncl: -40000` は一本計上前提。店別計上に移行した月は介護40,000が美容部門に来ないので残差が +40,000 ずれる（mode:'manual' のため自動判定は無い）。移行が確定したら RECON を月別に切り替える改修が要る（W-later）。

## 未決・保留（この ADR で決めなかったこと）

- 同日の突合で見つかった**真の差分**（6312 雇用保険の従業員負担分の貸方相殺・5211/6225 の返金/立替の貸方未相殺・4月 `welfare` 残骸2行・TkcCompare の 6219/6226 マッピング不整合）は本ADRの対象外。`aggregateBeauty` が費用科目の貸方を無視している構造が共通原因（facts F16）。
- 減価償却（6214 概算60,000/店/月）の実態（守口のエアコン？開業費？）はTKCの固定資産台帳で確認中。
